# 공개 게시글 상세 인계

2026-10-03 · Issue #6 · feature/6-public-post-detail · dev 통합 전, PR #3/#5에 의존.

홈 목록의 제목은 서버가 제공하는 author.handle과 urlKey로 /blogs/{handle}/posts/{postKey}에 연결한다. 내부 TSID를 상세 경로로 사용하지 않는다. 목록 DTO 검증에 handle/urlKey를 추가했다.

상세는 Guest/no-store GET /api/v1/blogs/{handle}/posts/{postKey}로 조회한다. 요청과 응답의 handle/urlKey를 대조하고 TEXT/CODE 블록의 유형·내용·언어·순서를 검증한다. 서버의 블록 배열 순서를 유지한다. TEXT는 일반 텍스트로 표시하며 HTML/Markdown을 실행하지 않는다. CODE는 pre/code와 내부 가로 스크롤, 복사 성공·실패 안내를 제공한다. 작성자·제목·요약·태그·날짜와 글 제목 메타데이터를 표시한다.

잘못된 주소/404는 같은 미존재 안내로 처리하고 다른 API/네트워크 실패에는 재시도를 제공한다. React cache로 동일 요청의 메타데이터/페이지 조회를 공유한다. 댓글·좋아요·편집·썸네일·개인 블로그 목록은 이번 범위에서 제외한다.

검증: Node 22에서 테스트 13개·빌드·타입 검사 통과. 목 브라우저의 홈→상세 이동, 스크립트 문자열의 텍스트 표시, 코드 복사 성공, 390px 코드 내부 스크롤/페이지 폭, 미존재 안내를 확인했다. 목 HTTP 상세 응답·깨진 블록·잘못된 경로·응답 주소 불일치는 테스트했다. 실제 로컬 백엔드의 미존재 상세 조회는 not-found로 분기했다. 실제 글이 있는 상세·운영 API·Workers는 미검증이다.
