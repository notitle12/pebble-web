# 사용자 프론트 기능 연결 현황

2026-10-04. 디자인 개편·adminweb·운영 배포는 사용자 프론트 기능 연결과 별도 범위다. 아래는 구현과 검증을 구분한 기록이며 완료율을 임의로 전체 서비스 출시율로 해석하지 않는다.

## 이번에 추가한 연결

| 기능 | 구현 | 확인 |
|---|---|---|
| 글 없는 블로그 프로필·폴더 | GET /blogs/{handle}의 공개 ID·이름 사용 | 실제 빈 블로그·빈 폴더 이동, Guest 요청 계약 |
| 내 글 순서 | 내 전체 공개·비공개 목록의 1 기반 입력을 displayOrder 0 기반 PATCH로 변환 | 브라우저 1→2→1 복원, 실제 API 전체 순서 보존 |
| 글·프로젝트 삭제 | 제목을 포함한 삭제 확인 후 DELETE, 프로젝트 연결 해제 안내 | 실제 새 비공개 테스트 글 2개·프로젝트 1개만 삭제·404·연결 글 보존·기존 순서 복원. 기존 콘텐츠의 브라우저 삭제는 실행하지 않음 |
| 블로그명·닉네임 수정 | 변경 필드만 PATCH, 고정 handle, 서버의 필드별 7일 쿨다운 | 프로필 모델 테스트, 실제 쿨다운 안내·변경 차단·미변경 안내, 백엔드 프로필 통합 테스트 |
| 로그아웃·탈퇴 예약 | 기존 로그아웃, 확인 후 DELETE /members/me, 예약 성공/불확실 결과에 인증 비움 | 세션 테스트, 실제 예약 확인 UI만 확인하고 실제 회원 탈퇴는 실행하지 않음 |
| 탈퇴 예약 취소 | /withdrawal/cancel에서 네이버 재인증, state에 묶은 취소 의도, POST /auth/naver/withdrawal/cancel 후 다시 로그인 | 일회용 요청·state 불일치·세션 미발급 테스트, 백엔드 탈퇴 통합 테스트. 실제 Naver 재인증은 미확인 |
| 글 썸네일 | 저장된 글 편집에서 PUT/DELETE multipart 관리, 공개 카드·상세 표시 | FormData 경계·Bearer·응답 유실 테스트, 실제 로컬 API 및 브라우저 STORAGE_UNAVAILABLE 503 안내 |
| 프로젝트 이미지 | 저장된 프로젝트 편집에서 대표/스크린샷 업로드·설명·순서·삭제, 공개 상세 갤러리·새 signed URL 조회 | 미디어 소유자/URL/파일/문자/순서/응답 계약 테스트, 실제 빈 관리 패널·375px 가로 넘침 없음, 백엔드 미디어 통합 테스트 |

프로젝트 이미지 설명은 최대 300 Unicode 코드 포인트다. R2 비활성·숨김·차단 콘텐츠의 URL은 null일 수 있어 저장 여부와 표시 URL을 혼동하지 않는다. 서버가 실제 파일 검증과 WebP 변환을 담당한다. 원본 파일·R2 키·OAuth 비밀은 프론트에 저장하지 않는다.

저장·삭제·순서 변경·이미지 처리는 자동 재전송하지 않는다. 응답이 불확실하면 변경을 잠그고 서버 상태 재조회로 복구한다. GET 실패가 불확실 상태를 해제하지 않는다. 회원 ID와 현재 세션을 확인하고 계정별 컴포넌트를 분리한다.

## 검증 결과

- Node 22 전체 프론트 테스트 109개 통과, Next.js 16.3.8 프로덕션 빌드와 TypeScript 검사 성공.
- 별도 빈 PostgreSQL DB에서 관련 백엔드 통합 테스트 90개 통과(공개 프로필·회원 프로필·탈퇴·Board·Post·Project·연결·미디어). 테스트 후 전용 DB만 삭제했다.
- 기존 로컬 DB에서 Project 집계 테스트 두 건이 준비된 공개 프로젝트 때문에 기대 개수와 달라 실패했다. 기존 데이터를 삭제하거나 테스트 기대값을 완화하지 않고 빈 DB로 재검증했다.
- 새 테스트 프로젝트 894510054541072797와 글 894510054738205545·894510055031804083은 논리 삭제했다. 실제 프로젝트 삭제 후 연결 글은 보존되고 projectId=null, 글 삭제 후 404, 기존 내 글 목록 수·ID·displayOrder 복원을 확인했다.
- 기존 테스트 글 894267440220573211·프로젝트 894436600529756465 및 기존 Board는 유지한다. 글 없는 블로그 표시용 fixture는 BOARDS.md에 기록했다.
- 실제 R2 저장 성공은 미확인이다. 현재 로컬은 R2_ENABLED=false이며 오류를 성공으로 표시하지 않는다. 백엔드 미디어 통합 테스트는 저장소 대역을 사용한다.
- 실제 Naver 공급자·HTTPS 쿠키·Workers 실행 검증은 아직 하지 않았다. 로컬 공급자 대역 검증과 운영 검증을 구분한다.

## 운영 연결 준비

사용자가 확인한 프론트 도메인은 `www.pebble-log.com`이다. 도메인은 Cloudflare에서 구매했으며 Oracle 서버와 연결되지 않았다. 백엔드는 현재 로컬에만 있다. API 운영 주소는 아직 확정되지 않았다.

다음 운영 작업은 Oracle 백엔드 실행·HTTPS·API 도메인 연결, 네이버 callback 및 허용 Origin 설정, R2 연결, Workers 런타임 구성·배포·실제 브라우저 검증 순으로 진행한다. 운영 callback은 프론트 주소 기준 `https://www.pebble-log.com/auth/naver/callback`이다. 실제 적용 전 API 주소·서버 배포 설정과 등록된 네이버 callback을 대조해야 한다. 백엔드 인증 비밀과 R2 키는 백엔드에서만 설정하며 프론트 NEXT_PUBLIC_API_BASE_URL에는 공개 API 주소만 둔다.

현재 저장소는 Next.js build까지 확인한 상태다. Workers용 어댑터/배포 설정과 실제 배포는 아직 완료하지 않았다. `api.pebble-log.com`은 선택 가능한 후보이며 확정된 주소나 이미 설정된 DNS로 기록하지 않는다. Cloudflare·Oracle 계정 변경과 실제 공개 배포를 실행한 것으로 보고하지 않는다.
