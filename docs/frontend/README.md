# Pebble 프런트엔드 설계 기준

기존 백엔드 문서와 프런트엔드 초안 문서를 수정하지 않고 추가한 설계 문서다. 제품 정책을 새로 정의하지 않고 백엔드 계약을 화면과 사용자 흐름으로 옮긴다.

## 읽는 순서

1. [작업 규칙](GUIDELINES.md)
2. [화면·권한·API 명세](SCREEN_SPEC.md)
3. [디자인과 시안 기준](DESIGN.md)
4. [계약 차이와 확인 사항](CONTRACT_GAPS.md)

제품 범위는 [백엔드 PRD](../../../pebble-api/docs/PRD.md), HTTP 계약은 [API](../../../pebble-api/docs/API.md), 인증·인가 정책은 [SECURITY](../../../pebble-api/docs/SECURITY.md), 저장·삭제 정책은 [DB](../../../pebble-api/docs/DB.md)를 따른다. 대조 기준은 백엔드 dev `682061a`이며 실제 구현 완료 기록은 백엔드 HANDOFF와 PR #57을 함께 확인한다.

## 현재 상태

- `pebble-web/src`는 참고 이미지를 기반으로 만든 초기 구현 초안이다. 최종 시안·전체 MVP 완료를 뜻하지 않는다.
- 초안의 인증 모의 테스트 7개와 배포 빌드는 통과했다. 실제 USER 로그인·프로필 저장·미디어 브라우저 검증은 아직 완료하지 않았다.
- 공개 목록의 실제 API 응답 및 예시 화면의 검색·상세 이동은 확인했다. 모바일 레이아웃·메뉴 검증은 사용자 요청에 따른 설계 정리로 중단된 상태다.
- 이 문서는 목표 화면과 기존 코드의 차이를 명시한다. 목표 라우트가 모두 구현돼 있다고 해석하지 않는다.
- 새 기능 구현 전에 공개 탐색·개인 블로그·내 관리 화면의 시안을 구분하고 계약 차이를 해결한다.

## 다음 순서

문서 대조 → 주요 화면 시안 재구성 → API가 부족한 정보 확인 → 디자인과 화면 흐름 확정 → 기능별 구현·검증 순으로 진행한다. 프런트엔드에 맞추기 위해 백엔드의 권한이나 토큰 정책을 임의로 변경하지 않는다.

## 작성 화면 구현 갱신 (2026-10-04)

사용자 `/posts/new`·`/posts/{id}/edit`·`/me/posts`에 시각 블록과 HIDDEN 비공개 저장·재조회를 연결했다. Naver 시작/callback·회원 refresh 복구·최초 블로그 설정 화면을 추가했으며 실제 API 저장과 공급자 대역 로그인 검증을 구분한다. 이전 초안의 미구현/검증 상태는 당시 기록이며 현재 범위와 남은 항목은 [게시글 작성 인계](POST_EDITOR.md)를 따른다.

2026-10-04 공개 게시 후속: 전체 미리보기와 공개/비공개 전환을 연결하고 기존 공개 상세 렌더러를 함께 사용한다. 실제 Guest 공개 조회 및 비공개 전환 후 404를 확인했다. 현재 기록은 [게시글 작성 인계](POST_EDITOR.md)의 공개 게시 후속 절을 따른다.

작성 분류 후속: 카테고리·태그 선택/검색, 기존 비활성 연결 복원, 변경한 연결만 PATCH 전송을 추가했다. 실제 API 지정·제거·보존은 확인했으며 이번 브라우저 검증은 도구 정책 차단으로 미확인이다. 상세는 [게시글 작성](POST_EDITOR.md)의 작성 분류 선택 후속을 따른다.

공개 홈과 개인 블로그 방향을 분리했다. 홈의 작성자 링크·/blogs/{handle}·내 블로그·글 관리 동선과 바로 시작하는 네이버 로그인 버튼을 연결했다. 실제 네이버 자격 증명이 없는 로컬 대역은 오류 이유를 안내하며 실제 네이버 로그인은 별도 검증이 필요하다. [홈·블로그·로그인 인계](BLOG_HOME_LOGIN.md)를 따른다.

공개 화면 디자인 갱신: 홈·프로젝트·개인 블로그·태그·주제·상세의 현재 시각 기준과 검증 결과는 [현재 디자인 기준](VISUAL_DESIGN.md)을 따른다. 초기 DESIGN.md의 색상 기준보다 우선한다.

기능 우선 진행 (2026-10-04): 사용자 요청에 따라 디자인은 후속으로 두고 실제 기능/API 연결을 우선한다. 글·프로젝트 상세의 댓글 목록·공개/비밀 작성·본인 수정/삭제·페이지 이동과 세션별 표시를 추가했다. 실제 검증 범위와 남은 항목은 [댓글 기능](COMMENTS.md)을 따른다.

프로젝트 작성·관리 후속 (2026-10-04): `/projects/new`·`/projects/{id}/edit`·`/me/projects`를 실제 회원 API에 연결했다. 공개·비공개 저장, 진행 상태·날짜·기술 태그·기능·링크 편집과 변경하지 않은 연결 ID 보존을 확인했다. 구현 범위·승인 및 로컬 데이터 기록·남은 검증은 [프로젝트 작성·관리](PROJECT_EDITOR.md)를 따른다.
