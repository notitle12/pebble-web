# 홈 검색·태그 구현 인계

2026-10-03 · Issue #4 · feature/4-post-search · 목록 PR #3에 의존, dev 통합 전.

GET /posts/search는 q가 있을 때, GET /posts는 q가 없을 때 사용한다. 두 조회 모두 tagId와 page·size를 전달한다. GET /tags의 공개 배열을 선택 항목으로 사용하며 비활성 항목도 서버가 반환하면 탐색을 허용한다. TSID/BIGINT는 문자열로 유지한다.

q·tagId·page는 URL에 보관한다. Next Form GET 제출은 page를 생략해 첫 페이지로 돌아간다. 페이지 링크·재시도는 현재 q·tagId를 보존하고 초기화는 /로 이동한다. 빈 q는 전체 목록이며 q 최대 200 Unicode code point, NUL·깨진 Unicode·중복 query·잘못된 tagId·알 수 없는 조건을 거부한다.

필터 결과 없음은 전체 빈 목록과 구분한다. 태그 조회 실패는 목록 조회와 독립적이며 검색어 조회를 계속 허용하고 기존 태그 조건을 보존한다. 폼 label, 초점, 모바일 세로 배치를 제공한다. 인증·클라이언트 store·검색 라이브러리는 추가하지 않았다.

npm run dev:mock에서 검색·태그를 확인한다. 목 데이터는 본문과 분류를 갖지 않으므로 제목과 태그의 부분 일치/AND만 구현한다. 실제 검색 API는 본문·분류도 검색하며 summary는 제외한다. 운영 오류를 목 데이터로 바꾸지 않는다.

검증: Node 22, npm test 11개·npm run build·npm run typecheck 통과. 목 브라우저에서 Spring+Java 결과 4개, 결과 없음, 새로고침, 뒤로 가기 시 실제 입력값 복원, 초기화와 모바일 가로 넘침을 확인했다. 페이지 조건 보존·특수문자 인코딩·Unicode 길이·BIGINT 경계·잘못된 응답은 테스트했다. 실제 로컬 백엔드의 공개 태그 8개와 검색+태그 0개 응답이 조회/검증 함수를 통과했다. 실제 글이 있는 검색·운영 API·Workers는 미검증이다.

기존 AGENTS.md 사용자 변경은 제외한다. PR #3이 아직 미병합이라 그 커밋 위에서 개발했고 dev 대상 PR에 의존 관계를 명시한다. 먼저 #3을 통합하면 새 PR에는 검색 변경만 남는다. 병합·배포는 수행하지 않는다.
