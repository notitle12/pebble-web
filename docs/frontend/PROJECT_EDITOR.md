# 프로젝트 작성·본인 관리 인계

## 구현 범위 (2026-10-04)

디자인은 후속으로 두고 실제 기능과 API 연결을 우선한다는 사용자 요청을 따른다.

- `/projects/new`: 프로젝트 생성과 공개·비공개 저장.
- `/projects/{id}/edit`: 본인 프로젝트 조회·수정, 공개 상태 전환.
- `/me/projects`: 본인 목록, 공개 상태 필터, 페이지 이동, 수정 동선.
- 상세 화면의 본인 수정 링크와 헤더·내 블로그의 프로젝트 관리 링크.
- 이름·요약·소개·기술 구성·실행 방법·진행 상태·시작일·완료일·기술 태그·주요 기능·외부 링크 입력.
- 기능·링크 추가·삭제·순서 변경. 기존 비활성 태그는 유지하거나 제거할 수 있지만 새로 선택하지 않는다.

## API와 저장 규칙

회원 세션의 기존 Bearer 인증을 사용한다. 생성은 `POST /projects`, 수정은 `PATCH /projects/{id}`, 본인 목록은 `GET /members/me/projects`를 사용한다. 조회 응답의 작성자와 요청 ID를 검증하고 BIGINT ID는 문자열로 유지한다. 로그인 복귀 경로에 위 관리 라우트를 추가했다.

수정 시 변경한 필드만 전송한다. 기능·링크·태그가 그대로면 배열을 생략해 기존 연결 ID를 보존한다. 빈 선택 문자열은 nullable 필드의 명시적인 null로 처리한다. 미디어는 이번 폼에서 수정하지 않는다. 저장 중 중복 제출을 막고 실패 시 입력을 유지하며 자동으로 쓰기 요청을 재시도하지 않는다. 차단된 비공개 프로젝트의 공개 전환은 허용하지 않는다.

문자 길이는 Unicode 코드 포인트 기준으로 검사한다. 날짜는 실제 달력 날짜인지 확인하고 타임존 변환 없이 YYYY-MM-DD로 전송한다. 브라우저 검증에서 날짜 입력 이벤트가 폼 상태에 반영되지 않는 문제를 발견해 onInput과 onChange 모두 상태에 반영하도록 수정했다. 링크는 사용자 정보가 없는 절대 HTTP(S) URL만 허용한다.

백엔드 API 문서 6.4의 본인 목록 미제공 설명과 실제 ProjectController의 `/members/me/projects` 구현이 다르다. 이번 기능은 실제 구현과 로컬 API 응답을 확인하고 연결했다. 기존 수정 중인 백엔드 API.md는 변경하지 않았다.

## 검증

- 프론트 전체 테스트 71개 통과, TypeScript 및 Next.js 빌드 성공.
- 실제 로컬 Spring API에서 생성·재조회·수정·공개 전환·비공개 전환 확인.
- 요약·진행 상태·날짜·공개 상태를 바꿔도 변경하지 않은 기능·링크·태그 ID가 유지됨을 확인.
- 공개 상태에서 Guest 조회 성공, 비공개로 되돌린 뒤 Guest 조회 404 확인.
- 관리 화면 비공개 필터에서 비공개 항목만 표시되고 공개 항목이 제외됨을 확인.
- 모바일 편집 화면에서 실제 콘텐츠 너비 375px와 scrollWidth 375px로 가로 넘침 없음 확인. 저장 버튼과 입력 화면을 시각 확인.

로그인은 로컬 공급자 대역을 거쳐 실제 API 세션을 발급하는 방식으로 검증했다. 실제 네이버 공급자 로그인·Workers 배포·R2 업로드는 이번 검증 범위에 포함하지 않는다. 배열 재정렬의 실제 API 저장, 비활성 태그 시나리오, 네트워크 실패·타인 수정·차단 상태의 브라우저 검증은 별도 확인이 필요하다. 입력·차이 계산·응답 소유권 검증은 단위 테스트에 포함했다.
