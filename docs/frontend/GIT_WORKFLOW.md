# Git 작업 순서

2026-10-03 사용자가 정한 컨벤션이다. 복원한 기존 문서를 수정하지 않고 별도로 기록한다. 저장소 초기화와 작업 절차 판단에서는 이 문서의 순서를 우선한다.

## 최초 프로젝트 구성

1. 프로젝트와 기본 실행 환경을 생성한다.
2. main 브랜치에 초기 구성을 준비한다.
3. GitHub 저장소를 연결하고 main을 올린다.
4. main에서 dev 브랜치를 만든다.
5. GitHub 저장소의 기본 브랜치를 dev로 설정한다.
6. 이후 작업부터 dev 기준 작업 브랜치와 이슈를 만들고 개발을 시작한다.

main은 릴리스 기준, dev는 개발 통합 기준이다. 기능·수정·문서 작업은 작업 브랜치에서 수행하고 dev 대상 PR로 통합한다. 최초 프로젝트 구성은 이 흐름을 시작하기 위한 초기 기준이다.

## 이후 작업

이슈의 목적·범위·완료 조건과 작업 브랜치를 작업 시작 시 함께 준비한다. 브랜치 이름에 실제 이슈 번호를 사용할 때는 이슈 번호를 발급받은 다음 브랜치를 만든다. 브랜치는 feature/<이슈번호>-<요약>, fix/, docs/, chore/ 규칙을 따르고 개발 도구·에이전트 이름을 붙이지 않는다.

## 이번 저장소 정리

초기 구성 커밋을 main·dev의 공통 기준으로 정리했다. 먼저 만들어졌던 chore/1-initialize-web 로컬 브랜치는 초기 구성을 두 기준 브랜치에 반영한 뒤 제거했다. 이슈 #1은 초기 구성과 문서 복원의 기록으로 남긴다. REPOSITORY_SETUP.md의 작업 브랜치·push 전 상태는 최초 구성 당시의 기록이며 현재 작업 기준은 dev다.

기존 MD 9개와 기능 코드는 이 정리로 수정하지 않는다. 초기 코드의 타입 검사·빌드는 이미 통과했으며 브랜치·문서만 정리하는 동안 동일 검증을 반복하지 않는다.
