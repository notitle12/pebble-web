# 개인 블로그 글 폴더 (2026-10-04)

## 범위

`/me/boards`에서 본인 Board 트리 조회·폴더 생성·이름/상위/표시 순서 수정·삭제 확인을 제공한다. ACTIVE USER이며 프로필 완료는 요구하지 않는다. 공유 Category와 구분되는 사용자 소유 폴더다. MemberGate와 기존 회원 세션을 사용한다.

작성기의 글 폴더 선택은 `/members/me/boards`를 사용하고 기존 연결을 복원한다. 조회 실패 시 기존 선택을 유지한다. 저장은 boardId 변경 시만 PATCH에 포함하고 미분류 선택은 명시적 null이다. ID는 BIGINT 문자열로 유지한다.

공개 블로그는 `?boardId=ID`로 폴더를 선택하고 `page`를 함께 보존한다. 공개 폴더 트리와 `/members/{memberId}/boards/{boardId}/posts`를 사용하며 직접 배치된 공개 글만 표시한다. 상위 폴더에서 하위 글을 합치지 않는다. 폴더 제목·전체 글·선택 상태·빈 목록을 표시한다.

## 무결성과 오류

트리 최대 3단계·중복 ID·내 트리의 parentId·표시 순서·응답 ID를 검사한다. 이름은 Unicode 1~50자, 순서는 0~2147483647 정수다. 입력에서 자기/자손 부모와 3단계 부모 선택을 제외하고 실제 이동·깊이·소유권은 서버가 최종 판단한다.

저장 중 입력과 중복 제출을 막고 쓰기 응답을 확인한다. 실패 시 입력을 유지하고 목록 재조회 전까지 재저장을 막는다. 사용자·mounted·조회 순서를 검사해 늦은 응답을 폐기한다. DELETE는 연결 글의 본문을 보존하고 미분류로 이동하는 서버 계약을 안내한 뒤 확인 버튼으로 실행한다. 하위 폴더가 있으면 삭제를 막는다.

## 실제 검증

- 전체 테스트 89개 및 최종 Next.js 빌드(TypeScript 포함) 성공.
- 실제 Spring API와 기존 로컬 공급자 대역 회원 세션 사용.
- 비어 있던 내 폴더 목록에서 생성·이름 변경을 브라우저로 수행.
- 테스트 폴더 894472495253365249: 최상위, 표시 순서 0, `[로컬 테스트] 백엔드 기록` 이름으로 남김.
- 테스트 글 894267440220573211을 폴더에 배치하고 공개 폴더에서 해당 글 표시 확인.
- 글을 원래 미분류(null)로 복원하고 기존 본문 4개 블록·카테고리·태그·프로젝트 연결 보존을 실제 API로 확인. 폴더의 빈 상태도 브라우저 확인.
- 공개 폴더 모바일 표시와 실제 너비/scrollWidth 375px 확인.
- 단위 테스트: 트리 깊이·부모·중복·ID·Unicode·정수·저장 응답·글 배치 차이·공개 URL 조건 보존·Guest 조회.

폴더 삭제·부모 이동·3단계 실제 생성·20개 초과 글의 실제 페이지 이동·응답 유실·타인 접근의 브라우저 검증은 미확인이다. 이번 생성한 빈 테스트 폴더는 삭제하지 않았다. 실제 Naver 공급자·Workers 배포 검증은 포함하지 않는다.

## 공개 글 없는 블로그 후속 (2026-10-04)

GET `/blogs/{handle}` 공개 프로필 API를 추가하고 화면을 연결했다. 이제 글에서 작성자를 추정하지 않고 프로필의 id로 공개 Board 트리를 조회한다. 공개 글이 없는 블로그와 빈 폴더도 이름·닉네임·handle·폴더를 표시한다. 위의 최초 구현 당시 제약은 해소되었다.

로컬 empty-blog-preview(member 910000000000009100, Board 910000000000009101)는 공개 글과 OAuth 인증 정보가 없는 검증용 프로필이다. 빈 블로그·빈 폴더 이동을 실제 브라우저로 확인했고 재확인을 위해 남긴다. API 계약은 pebble-api/docs/PUBLIC_BLOG_PROFILE.md, 현재 전체 기능 상태는 [기능 연결 현황](CONNECTION_STATUS.md)을 따른다.
