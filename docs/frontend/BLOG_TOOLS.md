# 개인 블로그 검색·사이드바 도구

개인 블로그 사이드바는 전체 방문자·오늘 방문자, 작성자가 설정한 GitHub 및 최대 5개 사이트 링크를 표시한다. 방문 통계는 `POST /blogs/{handle}/visits` 결과를 사용한다. 브라우저는 방문자 쿠키를 위해 요청에 credentials를 포함하고 본문을 보내지 않는다. React StrictMode의 effect 재실행은 handle별 진행 중 요청을 공유한다. 요청 실패 시 통계 오류를 안내하며 0으로 표시하지 않는다.

공개 링크는 `GET /blogs/{handle}/links`를 사용한다. GitHub는 `github.com`의 프로필 경로만 허용하고 사이트·로고 URL은 HTTPS만 화면에 표시한다. 외부 링크는 새 창으로 열고 안전한 `rel` 값을 지정한다.

`/settings/profile`의 별도 외부 링크 폼은 `GET /members/me/blog-links`로 초깃값을 읽고, 저장 버튼으로 `PUT`을 보낸다. 링크 목록 JSON의 `sites`에는 기존 ID를 보존한다. 로고 파일이 있을 때는 `links` JSON 텍스트와 `logo0`부터 시작하는 파일 필드를 담은 multipart를 보낸다. 새 사이트마다 PNG, JPEG 또는 WebP 로고가 필요하며 파일당 2MiB, 사이트당 이름 1~50자, HTTPS 주소 2048자까지 제한한다. 저장 결과가 불명확하면 자동으로 다시 쓰지 않고 서버 상태를 다시 불러오게 한다. 취소는 저장 시점의 값을 복원한다.

블로그 검색 폼은 선택한 개인 블로그의 공개 글만 검색한다. `GET /blogs/{handle}/posts?q=...`는 기존 공개 Post 페이지 계약에 `q`를 더하며 최장 200자다. 검색 제출은 폴더·프로젝트 화면과 페이지 번호를 초기화하고 페이지 이동은 검색어를 보존한다. 검색과 폴더 필터가 함께 있으면 잘못된 조합으로 안내한다.

사이드바 소유자 메뉴에는 `/settings/blog`의 “블로그 설정”만 표시한다. 관리 허브는 `MemberGate`를 사용하며 프로필/외부 링크, 게시판, 게시글, 프로젝트, 계정 설정 화면으로 연결한다. 각 대상 화면의 인증·소유권 판단은 기존 화면과 API에서 수행한다.

관련 로컬 계약 테스트는 `tests/blog-tools.test.mjs`와 `tests/public-blog.test.mjs`에 있다. 실제 쿠키 동작, API 허용 Origin, 업로드 저장과 화면의 실제 계정 검증은 프런트 단위 테스트 범위가 아니다.

사이드바 순서는 프로필 → 검색 → 게시판 → 프로젝트 → 방문자 → 소유자 블로그 설정 → 외부 링크다. 검색은 프로젝트 화면에서도 표시하며 돋보기 SVG 버튼과 접근성 이름을 제공한다. 블로그 설정은 톱니바퀴 SVG와 텍스트로 표시한다.
