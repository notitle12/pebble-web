# 글쓰기 이미지 수명과 블록 정렬

## 이미지 선택·저장 수명과 정렬 (2026-10-09, Web #59)

- 이미지 선택은 파일 형식·10MiB 제한을 확인한 뒤 바이트를 메모리에 복사하고 브라우저 object URL로 미리보기만 표시한다. 이 단계에서는 글 생성·이미지 업로드 요청이 없다. 저장 없이 나가면 브라우저 메모리와 object URL을 해제한다.
- 임시저장 또는 발행할 때 본문에 남아 있는 새 이미지만 업로드한다. 새 글은 먼저 이미지 없는 비공개 임시 글을 만든 뒤 첨부하고 실제 이미지 경로를 넣어 저장한다. 업로드 응답 URL을 사용하므로 직후 목록 재조회는 하지 않는다.
- 임시저장은 명시적 저장이다. 발행 글의 브라우저 임시저장에서도 새 이미지 파일은 해당 글의 첨부로 저장하고, 본문 변경은 공개 API에 반영하지 않는다. 저장 도중 실패하거나 응답이 불명확하면 이미 생성된 임시 글·첨부가 남을 수 있다. 결과를 모르면서 삭제하지 않으며, 같은 작성 화면의 재시도에서는 완료된 업로드를 재사용한다. 기존 업로드나 명시적으로 저장한 임시 글을 자동 삭제하지 않는다.
- 로컬 파일·blob URL·임시 참조를 서버 저장 본문이나 localStorage에 남기지 않는다. 편집 미리보기만 소유한 blob URL을 허용하고 공개 렌더링은 이를 거부한다.
- 이미지와 일반 표는 안전한 data-align 값(left/center/right)을 HTML에 저장한다. 코드·테이블 명세·아키텍처는 API 블록의 alignment(LEFT/CENTER/RIGHT)에 저장한다. 기존 블록은 LEFT로 처리한다. 구조 JSON을 HTML로 옮기지 않는다.

## 대표이미지와 목록 썸네일

- 별도 대표 파일 선택 창은 작성기에서 제거한다. 본문에 첨부한 첫 이미지가 기본 대표이고, 이미지 hover 또는 키보드 focus 시 `대표이미지 ✓` 버튼으로 바꾼다. 선택 이미지가 본문에서 제거되면 현재 첫 첨부 이미지로 돌아간다.
- 대표 선택은 편집 상태의 안정 src로 보관하고, 새 이미지 업로드가 완료되면 실제 body image src로 치환한다. 서버 저장 body에는 `thumbnailImageId` 문자열/null만 전달한다. 본문에 없는 ID 또는 외부 이미지 URL은 대표 후보가 아니다. 외부 URL을 서버에서 내려받지 않는다.
- API가 글 저장 트랜잭션에서 내부 본문 이미지로 작은 WebP 썸네일을 파생 저장하고, 응답의 `thumbnailImageId`로 편집 재진입 선택을 복구한다. 같은 선택이면 파생 이미지를 재생성하지 않는다. 기존 `/thumbnail` 파일 API는 구형 클라이언트 호환용이며 새 작성기는 사용하지 않는다.
- 내 블로그 목록 썸네일은 데스크톱 160×106, 좁은 화면 96×72 영역으로 표시하며 object-fit:cover로 자른다. 본문 이미지 크기는 바꾸지 않는다.

## 검증과 배포 상태

- 프론트 전체 테스트 183개·타입 검사·격리 Workers 빌드 통과. 합성 모의 API 브라우저에서 이미지 선택 시 업로드/글 생성 0회, 명시적 저장 시 업로드, 대표를 두 번째 이미지로 변경한 요청 ID, 일반 표 정렬을 확인했다.
- 백엔드 alignment·thumbnailImageId 계약이 선행돼야 한다. API 이슈 게시가 자동 승인 검토에서 거절돼 신규 계약의 병합·운영 배포는 보류했다. 로컬 테스트와 운영 R2 검증을 혼동하지 않는다.
