# 디자인과 시안 기준

첨부 이미지는 색감·공간감·조약돌 브랜드·개인 블로그 레이아웃 참고다. 이미지의 기능·숫자·상태를 제품 계약으로 받아들이지 않는다.

## 1. 유지할 시각 방향

- 옅은 푸른 배경, 흰색 패널, 네이비 글자, 파란 주요 포인트.
- 과한 카드 중첩 대신 간결한 목록, 부드러운 테두리와 약한 그림자.
- 투명 배경의 파란 조약돌 로고. 원본 참고 PNG와 현재 SVG 초안을 최종 브랜드 확정본으로 혼동하지 않는다.
- Naver 로그인 버튼은 녹색이며 공개 둘러보기와 로그인 오류를 함께 제공한다.
- 펼침/접힘 사이드바는 동일 메뉴의 두 상태다. 참고 이미지 양쪽 사이드바를 동시에 실제 UI로 만들지 않는다.

| 토큰 | 초안 기준 |
|---|---|
| 배경 | `#F2F6FC` |
| 패널 | `#FFFFFF` |
| 주요 글자 | `#17243D` |
| 보조 글자 | `#748198` |
| 주요 파랑 | `#356DFF` |
| 연한 파랑 | `#EDF3FF` |
| 테두리 | `#E7EDF6` |
| 본문·내비게이션 | 14~16px, 모바일 입력 16px 이상 |
| 제목 | 26~36px, 로그인 브랜드 48~56px |
| 간격 | 4/8/12/16/24/32/48px |

텍스트 대비·초점·줄바꿈·터치 영역을 실제 화면에서 확인하고 수치만으로 접근성 충족을 주장하지 않는다.

## 2. 다시 구성할 대표 시안

### A. 서비스 공개 탐색

```text
Pebble 브랜드 | 글 / 프로젝트 / 분류 탐색                 로그인 / 내 공간
제목: 개발자의 기록과 프로젝트를 만나보세요
검색 + 지원 필터
공개 Post 또는 Project 목록                  탐색 안내 / 실제 분류
각 카드: 작성자 · 제목 · 요약 · 기술 Tag · 서버 기준 상태/날짜
페이지 이동
```

여러 사용자의 콘텐츠가 섞이는 서비스 화면이다. 특정 블로그 이름·개인 소개를 서비스 전체 목록의 고정 사이드바에 표시하지 않는다. 게스트 헤더는 “내 공간” 대신 공개 탐색 의미를 전달한다.

### B. 개인 블로그

```text
블로그 이름·작성자                       글 / 프로젝트 / 아카이브
개인 Board 트리    | 선택한 블로그의 글/프로젝트 목록 | 최근 공개 글
                   | 검색·필터·페이지                 | 실제 기술 Tag
고정 handle 주소   | 상세: 본문/코드·댓글·좋아요       | 소유자의 허용 정보
```

첨부 프로젝트 시안은 이 화면의 시각 참고로 가장 잘 맞는다. 개인 Board·최근 Post·블로그 정보는 해당 작성자 범위의 데이터만 사용한다. 글이 없는 블로그의 헤더·회원 식별 계약은 CONTRACT_GAPS에서 먼저 해결한다.

### C. 내 콘텐츠 관리

```text
내 블로그 / 글 / 프로젝트 / 게시판 / 계정
내 콘텐츠 + 새 글/프로젝트 버튼
PUBLIC/HIDDEN 필터 · 차단 표시 · 작성자 전용 편집
본문/주요 기능/링크 편집 · 썸네일/미디어 · 공개 설정
프로필 미완료·정지·탈퇴 상태 안내
```

공개 탐색 화면에 편집 버튼을 무조건 붙이지 않는다. 상세의 소유자 편집 링크와 내 관리 화면을 연결한다. 차단 해제·사용자 콘텐츠 복원 버튼은 제공하지 않는다.

### D. 로그인·최초 설정

중앙 로그인 카드의 분위기를 유지하고 Naver 로그인 → 계정 상태 확인 → 최초 설정 흐름을 설계한다. 블로그명·닉네임·고정 handle의 의미와 중복 오류, 표시 이름의 변경 가능 시각을 안내한다. 일반 ID/PW 가입·다른 OAuth 버튼은 만들지 않는다.

### E. 관리자 운영

사용자 블로그와 별도 운영 탐색·관리자 로그인 화면을 사용한다. 목록 필터·상태·차단/해제·강제 삭제·감사 결과를 명확히 표시한다. MASTER 전용 메뉴와 MANAGER 메뉴를 구분한다.

## 3. 시안에 포함할 상태

각 대표 화면은 정상 데이터뿐 아니라 빈 목록·검색 없음·오류·모바일을 함께 검토한다. 추가로 로그인 만료, 최초 프로필 미완료, 본인 HIDDEN/차단, 이미지 URL 만료/null, SECRET 댓글, 탈퇴 취소 경계를 포함한다.

실제 전체 Project 수·진행 중 수·완료 수는 같은 범위와 실제 응답으로만 표시한다. 현재 페이지에서 계산한 수는 전체 통계로 표시하지 않는다. 고정한 예시 통계·계획 중 상태·제공되지 않는 SNS 연락처는 삭제한다.

## 4. 반응형·상호작용

데스크톱은 목록 + 보조 패널을 사용하고 좁은 화면에서는 보조 패널을 내용 흐름으로 옮기거나 생략한다. 모바일은 하나의 내용 열과 닫힘 상태의 메뉴를 사용한다. 닫힌 메뉴는 키보드 탐색에서 제외하고 열기·닫기·Escape·포커스 복귀를 검증한다.

검색·날짜·태그·긴 한글 제목과 handle이 세로로 좁아지거나 잘리지 않아야 한다. 콘텐츠 작성 중 화면 이동·실패·중복 저장을 설계한다. 테마·사이드바 설정은 콘텐츠 라우팅과 독립적으로 유지한다.

## 5. 시안 확정 조건

화면의 모든 주요 요소에 실제 데이터·API·권한 근거가 있고, 없는 정보는 계약 차이에 기록되어야 한다. 대표 화면과 모바일·빈/오류 상태를 함께 검토한 다음 초안을 수정한다. 시안 확정 전에는 현재 코드를 최종 UI로 홍보하거나 전체 프런트 완료라고 기록하지 않는다.
