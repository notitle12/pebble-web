# 공개 홈·개인 블로그와 로그인 동선 (2026-10-04)

사용자 방향: 홈은 여러 개발자의 블로그 글을 둘러보는 공간, 내 블로그는 개인 기록 공간이다. 홈에 특정 작성자의 정보를 고정하지 않는다. 큰 목록 카드와 커뮤니티 안내 문구를 줄이고 읽기 중심의 기록 목록으로 표시한다. 작성자 블로그명에서 `/blogs/{handle}`로 이동하며 개인 화면은 작성자 정보·공개 글·페이지 이동을 제공한다. 개인 목록에서는 작성자 이름 반복을 생략한다. 상세의 돌아가기 링크도 해당 블로그를 가리킨다.

헤더의 `내 블로그`는 `/me/blog`에서 본인 인증·프로필을 확인하고 고정 handle의 공개 블로그로 연결한다. `글 관리`는 `/me/posts`로 구분한다. 개인 블로그의 새 글/관리 링크는 로그인한 소유자에게만 표시하고 실제 쓰기는 기존 API의 소유권 검증을 유지한다. 공개 SSR은 Guest GET `/blogs/{handle}/posts`만 사용하고 모든 글의 handle 일치를 검증한다. 공개 글이 없는 블로그는 기본 정보 API가 없으므로 @handle만 표시하며 이름·소개를 추측하지 않는다.

`/login`은 정상 로그인 페이지로 유지한다. MemberGate·헤더·callback 오류의 네이버 버튼은 중간 `/login` 안내 페이지 없이 기존 authorization API를 즉시 호출한다. 중복 클릭을 막고 실패는 현재 화면에 표시한다. 프로필이 완료된 로그인은 `/me/blog`, `/me/posts`, `/posts/new` 중 시작한 경로로 돌아간다. 로그인 의도 경로만 sessionStorage에 저장하며 토큰은 저장하지 않는다. 외부 URL·임의 경로·query는 허용하지 않고 기본 `/me/posts`로 돌아간다. 미완료 프로필은 `/settings/profile`이 우선이다.

현재 로컬 API8081은 네이버 client-id가 local-preview인 공급자 대역이다. 이 값을 실제 네이버로 보내면 공급자 오류 화면이 나타날 수 있으므로 개발 모드에서는 이동 전에 실제 client-id/secret·등록 callback 설정이 필요하다고 안내한다. 실제 네이버 계정 로그인이 완료됐다고 주장하지 않는다. 실 로그인은 유효한 API 환경변수와 네이버 앱에 등록한 callback을 맞춘 뒤 별도로 검증한다. 자격 증명은 코드·Git·로그에 남기지 않는다.

검증: 공개 블로그 목록/주소/혼합 작성자 거부/빈 목록/API 404 테스트와 제한된 로그인 복귀 주소 테스트. 타입 검사·프로덕션 빌드 통과. 실제 API8081의 공개 글을 홈과 개인 블로그에서 브라우저로 확인했다. 게스트 내 글 버튼이 현재 화면에서 직접 authorization을 호출하고 테스트 설정 오류를 표시해 중간 안내로 이동하지 않는 것을 확인했다. 공급자만 로컬 대역인 실제 회원 로그인 뒤 헤더 `내 블로그` → 본인 공개 블로그 이동과 소유자 쓰기/관리 링크를 확인했다. 홈·개인 블로그 모두 390px 환경에서 document 폭과 scrollWidth가 375px로 페이지 넘침 없이 표시됐으며 viewport는 복원했다. 이전 브라우저 정책 차단은 이번 정상 HTTP 탭에서는 재현되지 않았다.

새 GitHub 이슈·PR 게시가 앞선 자동 승인 검토에 의해 보류된 상태이므로 이번 변경도 로컬 브랜치 `fix/blog-home-login`에 기록한다. 병합·배포는 실행하지 않는다.

최종 전체 테스트 51개·타입 검사·프로덕션 빌드 통과.
