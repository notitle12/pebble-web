# 게시글과 프로젝트 연결 (2026-10-04)

## 구현

게시글 생성·수정 화면에 본인 프로젝트 선택을 추가했다. 회원 목록 `/members/me/projects`를 20개씩 읽고 현재 페이지의 이름 검색·페이지 이동·로딩·빈 목록·오류 재시도를 제공한다. 기존 연결이 다른 페이지에 있거나 조회가 실패해도 ID를 유지한다. 프로젝트 이름을 아직 읽지 못한 기존 연결은 ID와 함께 표시한다. 프로젝트 관리 화면은 새 탭에서 연다.

API 6.3 계약에 따라 본인 미삭제 프로젝트만 선택하며 비공개·차단 프로젝트도 연결할 수 있다. 프로젝트의 공개 범위는 글의 공개 범위를 바꾸지 않는다. 서버가 최종 소유권을 검증한다. 타인 데이터를 섞지 않도록 목록 응답의 소유자를 확인하고 계정별 작성기 키와 effect cleanup으로 늦은 응답을 폐기한다.

OwnPost 응답의 projectId는 유효 BIGINT 문자열 또는 null인지 검사한다. 작성기 초기값으로 복원하고 변경했을 때만 PATCH에 전송한다. 연결 없음은 명시적 null, 미변경·undefined는 생략한다. 새 글은 선택값 또는 null을 생성 요청에 포함한다. 별도 의존성·인증 정책 변경은 없다.

## 확인

- 프론트 전체 테스트 74개 및 Next.js 빌드(TypeScript 포함) 성공.
- 실제 로컬 테스트 글 894267440220573211에 공개 프로젝트 910000000000003001 연결 저장, API 재조회 및 프로젝트 관련 글 목록 포함 확인.
- 편집 화면 새로고침 후 연결값 복원 확인.
- 비공개 프로젝트 894436600529756465로 변경 저장해도 글의 Guest 공개 조회 유지 확인.
- 연결 없음으로 저장해 원래 null로 복원. 기존 본문 4개 블록·카테고리·태그·공개 상태 보존을 실제 API로 확인.
- 모바일 실제 콘텐츠 너비·scrollWidth 모두 375px로 가로 넘침 없음, 선택기 시각 확인.

이번 검증은 기존 로컬 공급자 대역과 실제 Spring 회원 세션을 사용했다. 실제 네이버 로그인 및 배포 검증은 포함하지 않는다. 프로젝트 20개 초과 페이지 이동·빈 목록·오류·차단 프로젝트 연결의 실제 브라우저 검증은 남아 있다. 테스트 데이터 추가나 운영 데이터 변경은 하지 않았다.

## 후속

글 상세에서 연결 프로젝트로 이동하는 동선은 공개 프로젝트 조회 가능 여부를 고려해 별도 구현한다. 현재 프로젝트 상세의 관련 글 목록은 기존 구현을 재사용한다.
