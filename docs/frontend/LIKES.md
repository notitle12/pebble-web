# 글·프로젝트 상세 좋아요 (2026-10-04)

## 구현

공개 글·프로젝트 상세에 집계와 회원 좋아요/취소를 연결했다. Guest에는 집계와 네이버 로그인 안내를 제공한다. SSR 공개 집계를 초기 표시하고 기존 회원 세션이 준비되면 Bearer 상세 GET으로 내 likedByMe까지 재조회한다. Access Token 저장·refresh·CSRF·CORS 정책은 변경하지 않는다.

API 6.7 계약의 `/posts/{id}/like`·`/projects/{id}/like` PUT/DELETE를 본문·query 없이 호출하고 204(null)를 확인한 뒤 상세 GET으로 실제 상태를 읽는다. 프로필 완료는 요구하지 않으며 서버가 ACTIVE USER 및 공개 콘텐츠 조건을 검증한다. 대상 ID는 BIGINT 문자열로 유지하고 응답 ID·음수 없는 안전한 정수 집계·boolean을 검사한다. Guest likedByMe=true는 잘못된 응답으로 처리한다.

처리 중 연속 클릭을 막고 임의로 집계를 증감하지 않는다. 실패 시 상태를 불확실하게 표시하고 새로고침으로 실제 상태를 읽기 전까지 쓰기를 비활성화한다. 쓰기 자동 재시도는 없다. 회원·콘텐츠·세션 단계별 작성기 키, effect cleanup, 요청 revision과 현재 회원 검사로 늦은 조회·쓰기 응답을 폐기한다. 로그아웃 뒤 이전 회원 likedByMe를 표시하지 않는다. 403·404와 일반 조회 실패 메시지를 구분한다.

기존 목 데이터에는 likeCount=0·likedByMe=false와 숫자 ID 게시글 조회를 추가했다. 목 API는 Guest 집계 미리보기만 제공하며 회원 좋아요 쓰기를 흉내 내지 않는다. 기존 상세 fixture 호환을 위해 집계 필드를 생략할 수 있지만 지정된 잘못된 값은 거부하며, 좋아요 기능의 재조회 응답에서는 집계 필드가 필수다.

## 검증

- 전체 프론트 테스트 83개 통과. Next.js 운영 빌드 및 TypeScript 검사 통과.
- 실제 로컬 Spring API와 공급자 대역 로그인으로 회원 세션을 사용.
- 테스트 글 894267440220573211의 등록 0→1·취소 1→0, 새로고침 후 likedByMe 복원 확인.
- 테스트 프로젝트 910000000000003001의 등록 0→1·취소 1→0 확인.
- 등록된 글의 API Guest 집계 1·likedByMe=false와 회원 집계 1·likedByMe=true 확인.
- 모바일 실제 너비·scrollWidth 모두 375px, 버튼·집계 시각 확인.
- 최종 API 재조회로 두 콘텐츠의 집계 0·내 상태 false를 기존 기준과 대조해 복원 확인.
- 단위 테스트: 경로/ID·집계/응답 무결성·Guest 무인증/쿠키 제외·PUT/DELETE 무본문·204 및 실패 단회 호출·Post/Project 집계 파서·목 Guest 조회.

실제 Guest 로그인 안내 브라우저 화면, 다른 계정 전환·동시 클릭·응답 유실·403·404의 브라우저 검증은 남아 있다. 해당 경합 방지는 코드 검토 및 API 단위 검증과 구분한다. 실제 네이버 공급자와 Workers 배포는 이번 범위에 포함하지 않는다.

## 공개 목록 집계 후속

공개 홈·개인 블로그의 공통 글 카드와 프로젝트 목록 카드에 좋아요 집계를 표시한다. 같은 글 카드를 사용하는 프로젝트 관련 글 목록도 적용된다. Guest 목록 응답을 그대로 사용하며 추가 요청이나 회원 쓰기는 없다. 숫자는 ko-KR 단위 구분으로 표시하고 스크린 리더에는 “좋아요 N개”를 제공한다.

PostSummary·ProjectSummary에 선택적 집계 필드를 명시하고 목록 파서에서 음수·소수·문자열·unsafe 정수와 잘못된 likedByMe를 거부한다. 이전 fixture에서 집계가 생략된 경우 숫자를 만들어내지 않고 해당 표시를 숨긴다.

- 전체 테스트 84개 및 Next.js 빌드(TypeScript 포함) 통과.
- 실제 API의 홈·local-preview 개인 블로그·프로젝트 목록에서 집계 표시 확인.
- 세 화면 모두 모바일 콘텐츠 너비와 scrollWidth 375px로 가로 넘침 없음 확인. 홈 글 카드·프로젝트 카드 집계 시각 확인.
- 이번 후속에서는 데이터 쓰기 없이 조회만 수행했다. 실제 비영(양수) 목록 집계와 큰 숫자 시각 검증은 수행하지 않았고 단위 테스트에 1234 집계 보존을 포함했다.
