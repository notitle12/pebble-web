# 게시판 초안 편집 — Web Issue #47

`/me/boards`의 추가·이름 변경·삭제·이동은 서버에 쓰지 않고 화면의 초안 트리에 반영한다. 새 게시판은 중복되지 않는 `새 게시판`, `새 게시판 2` 순서로 트리 맨 위에 생기며 바로 이름 입력을 연다. 인라인 `확인`은 초안만 고치고, 전역 `변경 사항 저장`은 원래 전체 트리의 평탄화 기준과 초안 트리를 한 번의 `PUT /members/me/boards`로 보낸다. 성공 응답을 본인 트리로 파싱해 즉시 적용하며 재조회하지 않는다. `취소`는 원래 트리로 되돌린다.

드롭 대상 행의 위쪽 25%는 앞, 아래쪽 25%는 뒤, 가운데 50%는 하위로 즉시 이동한다. 자기 자신·자손·3단계 초과·같은 부모의 동일 이름은 초안에서도 차단한다. 키보드 이동은 Space → ↑↓ → →(하위) → Enter이며 Esc는 선택을 취소한다.

저장 기준 트리가 바뀐 `409 BOARD_TREE_CHANGED`와 응답을 알 수 없는 네트워크 결과에서는 초안을 유지하고 재저장을 잠근다. 사용자가 확인을 거쳐 서버 목록을 다시 불러오거나 초안을 버릴 수 있다. 저장하지 않은 변경 중 브라우저 종료와 내부 링크 이동은 확인한다. 계정 변경·언마운트 뒤 늦은 응답은 반영하지 않는다.

Node 22 전체 테스트 152개·타입 검사·격리 Workers 빌드 통과. 합성 API 브라우저에서 즉시 하위 이동·신규·이름 편집 동안 PUT 0회, 전역 저장 후 PUT 1회·추가 GET 0회를 확인했다. 삭제 초안과 취소도 서버 요청 없이 복원했다. 실제 운영 회원 데이터 쓰기 검증은 하지 않았다. 서버 트랜잭션·롤백·동시 변경 거부는 API #90 통합 테스트로 확인한다.
