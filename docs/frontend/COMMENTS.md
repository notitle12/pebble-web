# 댓글 기능 인계 (2026-10-04)

사용자는 디자인 조정은 나중에 하고 기능과 실제 API 연결을 우선하도록 요청했다. 다음 단위로 글·프로젝트 상세의 댓글을 연결했다. `feature/content-comments`는 앞선 로컬 작업 브랜치의 구현을 포함한다. 새 외부 Issue/PR는 생성하지 않았다.

## 구현과 계약

- `/blogs/{handle}/posts/{postKey}`와 `/projects/{id}` 아래에 공통 댓글 영역을 표시한다. 대상의 실제 API ID를 사용하고 BIGINT는 문자열로 유지한다.
- GET `/{posts|projects}/{id}/comments?page=N&size=20&sort=createdAt,asc`: 목록·개수·이전/다음·빈 페이지·조회 실패·명시적 다시 불러오기를 제공한다.
- POST: body·visibility를 전송한다. PUBLIC/SECRET 선택과 2,000 유니코드 코드 포인트 검증, 공백·NUL·깨진 서로게이트 거부를 제공한다.
- PATCH: 본인 댓글의 본문·공개 범위 수정. DELETE: 본인 댓글의 확인/취소 UI와 본문 없는 요청, 204 후 재조회. 마지막 항목 삭제 시 이전 페이지로 이동한다.
- 작성·수정·삭제는 기존 userSession의 Bearer 요청을 사용한다. 쓰기를 자동 재시도하지 않으며 요청 처리 결과가 불확실하면 입력을 유지하고 목록으로 확인하도록 안내한다. 동기 ref와 disabled로 중복 제출을 막는다.
- Guest는 쿠키·Bearer 없이 PUBLIC만 조회한다. Guest 응답에 SECRET이 있으면 응답을 거부한다. 회원 목록의 SECRET 접근 권한은 서버가 결정한다. 콘텐츠 작성자라도 타인 댓글의 수정·삭제 버튼은 표시하지 않는다.
- 댓글은 Client Component에서만 세션 복구 후 조회한다. SECRET을 SSR HTML이나 공용 캐시에 넣지 않는다. 계정/대상 변경 시 화면을 분리하고 세션·페이지 변경 이전의 늦은 조회를 무시한다. 로그아웃/복구 중에는 이전 회원 목록을 즉시 숨긴다.
- 로그인 후 유효한 공개 글·프로젝트 상세로 돌아오도록 내부 경로 허용 목록을 확장했다. query·hash·외부 주소·경로 이탈·잘못된 ID는 거부한다.
- 대댓글·관리자 운영·프로필 이미지·새 디자인은 이번 범위에 포함하지 않는다. 기존 네이버 로컬 공급자 대역과 실제 네이버 인증은 구분한다.

## 실제 검증

- 전체 테스트 59개 통과, 최종 TypeScript 포함 배포 빌드 통과.
- 실제 로컬 API(8081)/web(3100): 테스트 글에 공개 댓글 등록, 본인 수정·SECRET 전환, HTML 문자열의 일반 텍스트 표시, 본인 수정·삭제 확인/취소 UI 확인.
- 명시적 승인 후 테스트 댓글 20개를 생성해 전체 21개·2페이지를 확인하고 브라우저에서 두 번째 페이지로 이동했다. 승인된 20개만 API DELETE 204로 정리해 기존 비밀 테스트 댓글 1개를 보존했다.
- Guest API에서 SECRET 제외(0개), 실제 로그아웃을 다른 탭에 전달한 뒤 기존 글 화면에서도 SECRET·편집 버튼·작성 폼이 사라지는 것을 확인했다. 프로젝트의 실제 빈 댓글 목록도 확인했다.
- 모바일 콘텐츠 폭 375px에서 댓글·버튼·입력 폼 가로 넘침 없음.
- 삭제 최종 버튼의 브라우저 실행, 프로젝트 댓글 쓰기, 타인 계정의 수정/삭제 거부, 장애 시 UI 입력 보존, 계정 전환은 별도 실제 브라우저 검증이 남아 있다. 공통 세션·응답·입력·경로 검증 테스트 결과와 혼동하지 않는다.

자동 승인 검토가 초기 대량 댓글 생성/프로젝트 쓰기 계획을 거절했다. 이후 사용자가 승인한 것은 특정 로컬 테스트 글의 댓글 20개 생성·검증·정리이며 그 범위만 실행했다. 실제 네이버 OAuth와 운영 배포는 이번 검증에 포함되지 않는다.
